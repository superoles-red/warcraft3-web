Измерения сделаны на локальной сборке 1.31.1.12164 с русской локализацией. В таблицах 1 МБ = 1 000 000 байт. Файл `asset-sizes.json` рядом с отчётом содержит точные значения.

### Сжатие игровой графики без потери качества

Полный личный ZIP содержит 6 475 текстур BLP1. В 5 255 из них изображение уже закодировано JPEG, такие текстуры занимают 133,84 МБ внутри ZIP. У 1 220 текстур индексированная палитра, и обычный Deflate уменьшил их с 73,75 до 16,36 МБ. Внутри BLP остаются уровни детализации для разных масштабов камеры. Существующий рендерер загружает их в GPU для фильтрации изображения.

Сверка ключей содержимого CASC нашла 514 повторяющихся путей BLP, 24 пути MDX и 7 путей TGA. В полном исходном ZIP они суммарно занимают 13,52 МБ после сжатия. Для устранения этих дублей потребовались бы дополнительные ссылки между путями в формате пакета. В этой сборке графика остаётся в исходных форматах с исходными уровнями детализации.

## Девять роликов для браузера

Все девять видео извлечены из основного слоя CASC, а дорожки к ним — из ruRU. Исходное изображение 800 × 368, кодек VP9. Утилита переносит сжатые видеопакеты в WebM и кодирует звук в стерео Opus с целевым битрейтом 80 кбит/с. SHA-256 объединённых видеопакетов совпал до и после упаковки у каждого из девяти роликов. Продолжительность звука и изображения сохраняется отдельно, максимальная разница длин исходных дорожек составляет 0,45 секунды.

| Вариант | МБ |
|---|---:|
| Внешние AVI репака и все внешние варианты звука | 445,36 |
| Выбранные оригинальные VP9 и одна русская дорожка на ролик внутри CASC | 217,36 |
| Готовые WebM в `local/movies`, 26 минут 19 секунд | 206,23 |

Большая часть разницы в первых двух строках обусловлена выбором версии видео и локализации. Перекодирование звука и смена контейнера дают ещё 5,1% от объёма выбранных дорожек.

Дополнительный опыт на 15 секундах внешнего `humanop.avi` с отметки 00:50 проверил более компактный профиль. При ширине 640 пикселей, исходной частоте, VP9 CRF 32 и realtime 8 видео без звука заняло 788 743 байта. SSIM составил 0,966 в сравнении с тем же фрагментом оригинала после уменьшения до 640 пикселей. Влияние уменьшения разрешения этот показатель не учитывает.

## Игровой звук компактного пакета

| Материал | Файлы | Исходный размер, МБ | Компактный размер, МБ |

| Короткие WAV, в том числе ответы юнитов и эффекты | 3 871 | 406,46 | 58,27 |
| Длинные WAV, в том числе стереоокружение | 32 | 574,21 | 145,55 |
| Русские реплики кампаний | 2 436 | 176,46 | 97,88 |
| **Всего перекодировано** | **6 339** | **1 157,13** | **301,70** |
| Музыка в исходном MP3 | 44 | 100,37 | 100,37 |

Короткие WAV кодируются в Opus VBR с целью 48 кбит/с для моно и 88 кбит/с для стерео. Для диалогов из исходных MP3 выбрано 44 кбит/с. В предварительном опыте перекодирование музыки Human2 дало только 13% экономии, поэтому в готовом пакете музыка сохранена побайтно. В таблице учтены логические имена до дедупликации внутри игрового ZIP.

Для WAV длиннее 15 секунд используется IMA ADPCM. Такой формат позволяет синхронно открыть большой стереофон при загрузке карты. На тестовом Mac декодирование 44,77 МБ звука одного городского фона заняло около 0,13 секунды процессорного времени. Браузер распаковывает только запрошенный ресурс в память. Для каждого WAV сохраняются число каналов, частота, точное число отсчётов и дополнительные RIFF-данные, включая метки циклов. Пути диалогов внутри сценариев остаются прежними. При проверке всего набора игровой декодер успешно прочитал 1 111 423 335 кадров в 6 339 файлах. При одновременной упаковке игры самый долгий синхронный декод одного фона занял 2,40 секунды по настенным часам, поэтому время загрузки местности ещё предстоит проверить на телефоне.

В Chrome на Mac с приватным ZIP игра открыла «Оборону Странбарда» и запросила через файловую систему реплики Артаса и пехотинцев и боевые эффекты. На выходе микшера SDL зарегистрирован сигнал при 44,1 кГц. Отдельное воспроизведение русской реплики `h01arthas02.mp3` через ту же файловую систему подтвердило длительность 4,426 секунды и сигнал на выходе Web Audio. Замер на физическом Samsung и субъективное сравнение всей фонограммы предстоят.

Подготовку и проверку звука можно повторить из корня проекта.

```sh
python3 tools/audio_compact.py
node tools/audio_verify.mjs
```

Целевые 300–500 МБ для полного набора с обеими кампаниями ещё не измерены. Одни модели и текстуры выбранного профиля занимают 314,54 МБ до транспортного сжатия. Вместе с комплектом видео они занимают 520,77 МБ до учёта карт и игрового звука. Для бюджета первого запуска можно подгружать ролик, локацию и речь по главам. Размер такой подборки зависит от состава миссии и проверяется отдельной игровой трассировкой.

## Готовый пакет первой главы

Локальный ZIP `local/Warcraft-III-Human01-mobile.zip` занимает 457 657 153 байта (457,66 МБ). В нём 12 408 записей на 638 574 259 байт после распаковки. Правила, модели, текстуры, озвучка и музыка сохраняют исходный формат игры. Внешний ролик, предваряющий кампанию, доступен в локальном комплекте видео. Встроенные сцены первой миссии воспроизводятся по сценарию карты.

Профиль открывает оригинальную главу Альянса «Оборона Странбарда» (`campaign/human01.w3m`). В пакет включены все 34 файла из каталога речи Human01 и четыре реплики из Human03, к которым обращается сценарий первой главы. Проверен CRC всех записей. Из 72 прямых ссылок в JASS карты доступны 71, в том числе восемь ресурсов под стандартными расширениями MDX и BLP. Последняя ссылка переводит кампанию на Human02. Для следующей главы понадобится другой пакет. Все 1 086 уникальных файлов из проверенной трассировки присутствуют в ZIP. Эти проверки охватывают состав пакета. Завершение главы в браузере требует отдельного прохождения.

Для повторной сборки выполните `python3 tools/make_human01_profile.py` из корня проекта после подготовки игрового зеркала. Список путей `tools/human01-startup.txt` добавляет 27 ресурсов, запрошенных стартовым меню и картой сражения в той же проверке. При наличии собственной записи запросов параметр `--trace` добавляет наблюдавшиеся файлы.

## Воспроизведение измерения

Для этой Inno-сборки достаточно извлечь игровые данные из локальной копии. В командах ниже `INSTALLER` указывает на setup.exe, а `WORK` — на каталог для личных файлов игры. Для видеоподготовки нужны FFmpeg и FFprobe с кодеком libopus. Компактный режим также использует libvpx-vp9.

```sh
innoextract -s --collisions rename -d "$WORK" -I app/Data -I app/.build.info "$INSTALLER"
python3 tools/prepare_game.py "$WORK/app" --cache "$WORK/tools"
python3 tools/asset_sizes.py "$INSTALLER" "$WORK/tools/casc-inventory.tsv"
python3 tools/prepare_movies.py --install "$WORK/app" --cache "$WORK/tools"
```

Команда подготовки роликов создаёт `local/movies/<имя>_native.webm` и `sizes.json` с длительностями и размерами отдельных дорожек. Для отдельного сравнения пониженного разрешения добавьте `--compact --output local/experiments/movies-640`. Основной проигрыватель по умолчанию запрашивает `_native.webm`.
